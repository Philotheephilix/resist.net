# resist.net — Architecture

## Overview

Two composited systems in one volunteer network:

1. **Probe Layer** — volunteers run HTTP/DNS/TCP reachability checks from their region/ISP. Results are wallet-signed, chained, and written to Arkiv.
2. **Proxy Layer** — volunteers publish WebRTC SDP offers to Arkiv with a 5-min TTL. Censored users query Arkiv, find a live peer outside their blocked region, complete P2P WebRTC handshake.

Arkiv is the backbone of both: tamper-evident probe archive + self-cleaning proxy directory.

## Data Flow

### Probe Flow
```
Volunteer node
  → runProbe() — HTTP + DNS + TCP checks
  → sign result with device wallet
  → chain to previous result hash
  → write to Arkiv (entity: ProbeResult, TTL: 30 days)
  → if offline: cache to local SQLite
  → on reconnect: drain SQLite → Arkiv
```

### Map Query Flow
```
Map UI
  → query Arkiv: ProbeResult where geohash=X AND reachable=false AND timestamp > T
  → group by targetUrl + isp
  → render heatmap of blocks
```

### Proxy Flow
```
Volunteer
  → create RTCPeerConnection
  → generate SDP offer
  → write to Arkiv: VolunteerProxy { wallet, sdpOffer, geohash, TTL=5min }
  → refresh TTL every 4 min

Censored user
  → query Arkiv: VolunteerProxy where geohash_prefix != myRegion
  → pull sdpOffer
  → generate SDP answer
  → exchange answer with volunteer (via Arkiv or direct)
  → WebRTC peer-to-peer channel established
  → route HTTP through channel
```

## Block Classification

| Condition | Block Type |
|---|---|
| DNS expected ≠ DNS received | `dns_poisoning` |
| TCP connect → ECONNRESET | `tcp_rst` |
| HTTP timeout / 5xx | `http_block` |
| All three fail | `full_unreachable` |

---

## Offline Resilience

- Node loses internet → SQLite cache stores probe results (signed at probe-time)
- Each result includes `prevResultHash` — chains all results from a device into a verifiable sequence
- On reconnect → batch drain to Arkiv
- Map marks synced-from-cache results with a `cached: true` flag until corroborated by ≥3 other nodes

---

## Honest Limits

- Hard blackouts (fiber cuts, BGP withdrawal): offline cache runs, Arkiv sync and proxy matchmaking pause
- Symmetric NAT (~15% of mobile connections): WebRTC STUN alone insufficient, TURN relay needed
- Arkiv endpoint blocked: bootstrap from pre-cached volunteer list (refreshed whenever online)
- Volunteer legal exposure: app routes to specific services only, not open-proxy; clear opt-in disclaimer
